## Unreleased

- Example ranges (linux-examples-v1): three published range definitions promote from translated fixtures to BUILT, VERIFIED, SOLVED examples under `examples/`, each with recipes realizing its declared guest content, a behavioral check trio proving every challenge at build (reference 1.0, insufficient and forged 0.0), and a real `inspect eval` solving it through its declared foothold: `kypo-demo` (the KYPO telnet ladder: a routed two-subnet topology with an explicit router, telnetd on a variable port, a wordlist-guessable password, the sudoers `less` escalation), `cyris-basic` (the CyRIS reference: a firewall-as-router carrying the upstream 25/53 forwarding ACL, weak-root-password privesc, forensics triage of deterministically synthesized captures and a resident dummy process), and `mhbench-equifax-small` (the Equifax model at scale: six targets, CVE-2017-5638 Struts entry asserted live at build, a planted SSH-key pivot, four coverage-scored exfiltrate canaries with pcap corroboration, and the attacker as the catalog default). Substrate work the examples forced: declared `variables:` resolve to their defaults at planning (per-sample secrets stay the challenge plant layer's; the generation layer is a recorded deferral); the build claims the recipe-realizable sections (`users`, `misconfigurations`, `data` join `provisioning`/`services`/`vulnerabilities`); routed topologies build via a build-only NAT uplink segment and a provisioned foothold's attacker containment lifts for the build only; multi-homed guests elect their default route deterministically; a router with no `acl` is a plain router (everything forwards; declaring any rule keeps default-drop allowlisting); behavioral chains exec on the foothold host when a range has no dedicated attack box; in-guest hostnames sanitize to RFC form with plan-time collision refusal (docs: Example Ranges, Networks, Building).

- Image catalog (standard-images-v1): the standard images publish under `docker.io/meridianlabsai`, each consumable by bare name and pinned by digest. The `attack` image is the kali-class attack box (nmap, netcat/socat, tcpdump, impacket, sqlmap, hydra, john, gobuster, ffuf, smbclient, ldap-utils, and metasploit from its official repo with the release key fingerprint-pinned), recipe-built over the noble golden with the delivered package set recorded in-image (`/etc/attack-image.manifest`) and a build-failing zero-non-loopback-listener containment invariant. A dedicated attack box that declares no `image:` now boots it by default (migration: such attackers previously booted the default guest image; declare `image: ubuntu-noble` to keep the old behavior). `inspect-ranges publish` promotes built guests (`--guest/--as`), goldens (`--golden`), and the daemon artifact (`--daemon`) to a location whose catalog list updates with each image; `daemon-bundle --pull` fetches the published daemon artifact without a Go toolchain, and both the catalog list and the daemon bundle travel with whole-location mirrors. Eval init now pulls catalog images implicitly too (the attacker default, bare-name goldens), so a clean machine's first eval needs no explicit fetch verbs and warm evals still cost zero network. Fleets pin with `images pin` (names to root digests, consumed as `@sha256` pins) and pin the hardened range container image itself with `INSPECT_RANGES_RANGE_IMAGE=repo@sha256:...` (pulled once by `up`; mutable tags refuse; the local build stays the default and the dev loop) (docs: Image Catalog, Distribution).

- Distribution (distribution-v1): built ranges publish and consume across three interchangeable location forms (the public hub, private OCI registries, and plain OCI-layout directories for the air gap), joined to specs by the normalized-spec hash. `inspect-ranges push` publishes a build's transitive closure (dedup by digest); bare `pull` resolves the build matching the local `range.yaml` exactly (refusing `no-build-for-spec` with the nearest published build named) and `pull name@sha256:...` works with no spec in hand; the provider pulls implicitly at eval init with docker-pull-shaped progress and clean prerequisite refusals, warm evals cost one hash and zero network, and `INSPECT_RANGES_NEVER_PULL` pins a host against implicit transfers. Catalog images fetch via `images pull` (sticky) and move forward only via `images refresh` (whole chain, atomically staged). `mirror` seeds or syncs whole locations (every published build, not just latest), moves single builds spec-driven for the cross-group case, and the directory form tars across air gaps with everything still verifying. `images prune --chains` reclaims unreferenced golden/vendor chains under a cache-wide lock shared with every landing path, never a backing from under a dependent; `up` now verifies the full backing chain including the golden-to-vendor edge, so a mixed cache refuses instead of booting silently; doctor gains Distribution rows. The search path is `INSPECT_RANGES_REGISTRY` (ordered, first match wins, deployment registries shadow public names deterministically; a broken location aborts rather than silently de-shadowing). Proven live by five batteries plus a recorded conformance run against the real Docker Hub (production token flow, presigned-storage redirects with the bearer token stripped cross-origin, measured anonymous rate limits), and the Journey B transcripts executed as the phase exit (docs: Distribution).

- The attacker gains an opt-in `provider: glovebox` field (a.k.a. managed-external; default `ranges`, so existing ranges are unchanged). When set, an external manager (a glovebox Kata/Cloud Hypervisor agent cell) supplies the attack box: Ranges still reserves the box's segment IP/MAC and stands up the bridge, but does not render, boot, or list it in `boot.json`. `provider: glovebox` is mutually exclusive with both `vmm:` (glovebox chooses its own VMM; `provider-vmm-conflict`) and a `host:` foothold (`provider-foothold-conflict`), refused at validation (docs: Sandbox Provider).
- `provider: glovebox` integration glue (`_host/glovebox.py`, route-2 spike): a `glovebox_connector` behind the applier's injectable `GuestConnector` seam that serves an externally-supplied cell in-process over the v3 wire protocol, mapping `exec`/`read_file`/`write_file`/`ping` to the cell's `crictl exec` channel (`CrictlCellExecutor`), so `sandbox("attacker").exec(...)` lands in the cell unchanged; and a bridge-netns handshake that makes the glovebox segment's bridge node-reachable with a veth pair from the range container's in-netns segment bridge to a node-side bridge (`glovebox_segments`/`stitch_commands`/`cell_cni_conflist`), where the cell's CNI attaches on the reserved address. Validated end to end on a live range: a Kata cell on the reserved dmz address reaches the real `web` guest over the stitched dmz, and the connector drives exec/file ops into it through the real `MessageChannel`. Not yet wired: provider `sample_init`/applier relay-map registration of the glovebox guest as the sample's attacker sandbox.
- Docs: a dedicated [Custom Goals](docs/goals.qmd) article covers creating new goal types (the `GoalType` contract, the oracle surface, proof-design rules, assurance labels, testing, and registration); the Challenges article's section now points there. The closed v1 `challenges.yaml` type union is recorded in the article's registration section as the open concern.
- Every QEMU guest runs as its own unprivileged uid (issue #5): a per-domain static DAC seclabel (`GUEST_UID_BASE + cid`, the Cloud Hypervisor scheme) carries the per-VM boundary; `security_driver = "none"` stays and disables only the MAC slot, since sVirt AppArmor cannot load per-VM profiles inside the hardened container (the outer jail denies CAP_MAC_ADMIN and securityfs by design), which is now documented where the setting lives. The boot script pre-owns each guest's overlay, seed, and console log; libvirt never chowns a shared backing golden.
- The agent-containment section-6 defender-to-agent negative checks are automated (issue #6): the build's proof boot runs a `conformance` stage before the behavioral checks (a shared-segment defender TCP-sweeps the attacker; the attacker checks reserved hypervisor addresses answer nothing beyond their allowed service and unreserved gateway candidates are silent), and any finding refuses the manifest. Scope: TCP only, dedicated attack boxes only (foothold ranges skip the stage).
- BREAKING: the sandbox provider is registered as `range` (was `libvirt_range`, with no alias kept): `sandbox=("range", "range.yaml")`. The old name described an implementation detail that no longer covers the default attack box, which boots under Cloud Hypervisor with no libvirt in its path.
- The range container's segment bridges no longer have IPv6: the rendered compose sets `net.ipv6.conf.default.disable_ipv6=1` in the range's network namespace, so the bridges and taps created after it send no router solicitations, MLD or DAD frames and do not answer `ff02::1`; the bridges are also created without multicast snooping, so they send no IGMP report of their own and flood multicast to every port, like a plain switch. Guest-to-guest IPv6 still crosses the bridges; the host's IPv6 setting is unchanged.
- Guests no longer get q35 legacy devices that no configuration names and no guest uses: the domain XML turns off the VMware backdoor port and the HPET natively, and the SATA AHCI controller, SMBus (with its SPD EEPROMs), i8042 keyboard controller and kvmvapic through QEMU arguments (libvirt 10.0 has no elements for them). The PIT and PIC stay on.
- Hosts and routers gain a `vmm: qemu | cloud-hypervisor` field (default `qemu`); the agent/attacker box now defaults to `cloud-hypervisor`, so an existing range's attacker box moves from QEMU to Cloud Hypervisor (declare `vmm: qemu` on the attacker to keep QEMU). A Cloud Hypervisor guest boots directly from the boot script as an unprivileged per-guest uid with no domain XML and is reached over its hybrid-vsock Unix socket with an `SO_PEERCRED` peer check, and the range image carries the pinned Cloud Hypervisor binary and firmware (docs: Sandbox Provider). Migration notes: the new field changes the normalized spec form, so build manifests recorded before this release fail the gate's spec-revision match and consumers refuse until one rebuild per range (guests are reused: build keys do not include the field; declaring `vmm: qemu` on the attacker reproduces the pre-flip hash exactly, keeping an existing manifest valid). A foothold attacker (`host:` set) now refuses ANY declared `vmm`, including a redundant `vmm: qemu` that previously validated.
- Challenges: `challenges.yaml` defines what an agent is asked to do and how success is verified; `challenge_dataset()` builds the Inspect dataset (validated against the range), `plant_goals()` plants per-sample proof material and starts observers, `challenge_scorer()` verifies and aggregates with validity states. Fourteen goal types ship (flag, answer, exfiltrate, execute, control/privilege, hijack, degrade, tamper, availability, detection, evade, judge, patch), proofs anchored by per-sample secrets, a nonce-bound active prober on a clamped probe endpoint, exported telemetry, and evidence corroboration that can invalidate a sample on contradiction but never fails one on missing coverage (docs: Challenges).
- The provider registers only the foothold as the sample's sandbox by default (the agent/target wall); `INSPECT_RANGES_REGISTER_ALL_GUESTS=1` is the loudly-logged development opt-out (docs: Sandbox Provider).
- The six example ranges' `challenges.yaml` files migrated to the typed schema; reference intrusion chains with behavioral checks (reference passes via the foothold alone, insufficient fails, cheapest forgery fails) run in the devbox battery.
- Evidence: every sample records tamper-evident evidence outside the VMs (per-segment pcap via a `NET_RAW`-only sidecar, continuous consoles, stage/verification streams, daemon session continuity, poll-based in-guest telemetry export), streamed as generated to `<evallogstem>.evidence/<sample>_<epoch>_<attempt>` (local or S3, write-once conditional puts) with a hash-chained manifest, explicit in-chain gap records, per-writer seals, and the seal digests bound into the eval log's sample store; `inspect-ranges evidence verify [--expect-seal]` replays a record offline (docs: Evidence).
- Evidence capture runs tcpdump packet-buffered (`-U`): the active pcap chunk is current while the capture runs, and a capture killed rather than stopped keeps every packet it saw.
- `inspect-ranges doctor` gains the Evidence group: evidence knob validity, a sink writability probe when `INSPECT_RANGES_EVIDENCE_SINK` is set, and an off-instance warning for local-only evidence.
- CI enforces the C# codec drift guard: the py-test job installs the pinned .NET SDK (8.0.404 by sha256) and sets `INSPECT_RANGES_REQUIRE_DOTNET=1`, so three-codec parity fails loudly in CI instead of silently skipping.

- Host topology: every sample now holds a renewable host lease (`leases.json`), reclaimed by the new independent `inspect-ranges reaper` on expiry alone; `INSPECT_RANGES_HOST=uds:<socket>` selects the separated topology, where a standing `inspect-ranges applier` process owns realization and teardown and relays guest operations over one unix socket (docs: Host Topology).
- `inspect-ranges doctor` gains the Host group: strict `leases.json` health, an expired-leases hint naming the reaper, and an applier socket probe when one is configured.
- `range` Inspect sandbox provider: per-sample realizer-booted ranges with named sandboxes, layered retries with session invalidation, interrupted-sample containment, and `inspect sandbox cleanup range` crash recovery (docs: Sandbox Provider).
- `inspect-ranges doctor` gains the Provider group: entry-point registration, the inspect-ai floor, current-recipe goldens (with stale-golden guidance), and CID lease registry health.
