# Record: the pre-release development changelog

Status: retired 2026-10-26 at the v1 release boundary. This is the project's entire pre-release `CHANGELOG.md` (one Unreleased section accumulated across the whole development arc, 2026-09-30 to 2026-10-26), moved here verbatim so the first published release starts from a clean changelog. Entries read newest-first; the design records they cite live beside this file.

## Unreleased

- terminal() casts carry agent attribution: each session records the agent context that opened it (the enclosing agent span id, the denormalized agent name, and the opening tool call's span id), captured at open time because sample finalize runs outside every span, and emitted as additive `ir_*` fields on the asciicast header (store casts and evidence cast files alike). Asciicast parsers ignore unknown header keys, so older casts present flat and older players are unaffected; a viewer can group sessions per agent by joining `ir_agent_span_id` against the transcript's span tree, the same join inspect_ai already does for `ToolEvent.agent_span_id`.

- Telemetry windows no longer wedge or over-poison (the thirteenth scoring-integrity amendment, from the pre-ship fleet pass where splunk's execute-and-confirm read indeterminate after a boot-race gap marker pinned the export cursor into 273 consecutive failed polls). The poller re-bootstraps after `REBOOTSTRAP_AFTER_FAILURES` (5) consecutive failures on one cursor, with the streak's `poll-failed` gap owning the lost window and the re-bootstrap visible on the meta stream; `detection`/`evade` completeness is window-scoped (gap wall spans travel through `oracle.telemetry_export`, whose third element is now those spans rather than a whole-stream flag), so a gap that ended before the window opened leaves it decidable, while stealth verdicts treat any gap after the pipeline's first flow as a violation (activity cannot hide inside an induced gap behind a clean trailing window); and the splunk example's endpoint bridge treats a fresh-boot RecordId regression as a markerless bootstrap while an in-session regression is an unconditional marker (strictly louder against log clearing). The splunk example rebuilds (recipe content keys the build).

- The example tasks' default wiring is `scorer=challenge_scorer()` alone: `range_apparatus` leaves the shipped scorer lists (and the README/docs wiring snippets) now that phase-1 development is closed, repositioned as the range developer's diagnostic (wire it beside the scorer while building a range, or `scout scan` over finished logs; [Building](building.qmd#scan) is its home). Nothing changes in the library: the scanner was never a library default, and the apparatus column's lower-is-better reading beside accuracy was noise for eval consumers.

- inspect-ai floor moves to 0.3.285 (terminal UI improvements in the viewer's session playback).

- Challenges: the 8-candidate anti-oracle bound now holds at all three verification sites; the mid-run poller previously verified every distinct submitted value uncapped on its next tick, so a flood past `verify_goal`'s cap could still latch a pass (pre-ship review P0-1). The poller now verifies only the earliest 8 distinct values per goal (the scorer's rule), and overflow remains recorded and visible as `candidates_dropped` in the score metadata. Also: a goal latched achieved mid-run can now record `corroborated: false` from the scorer's full check; previously the end-of-run `false` was discarded and the result read `null` (no observer declared) instead of `false` (a declared observer found nothing). `true` still never downgrades, and an achieved latch is never un-achieved or re-timestamped (P1-5).

- `evidence verify --expect-seal` now anchors the writer set: a writer present at the location but absent from the supplied binding is a `writer-unbound` break (the finalize-time binding names the complete writer set, so a fabricated extra writer no longer verifies OK under the full guarantee; bare verify keeps its internal-consistency-only scope). Supplied digests accept an optional `sha256:` prefix; the documented example previously showed a prefixed digest a pristine record would fail against, and now shows the bare hex the binding actually stores (pre-ship P1-4, P1-9).

- terminal(): blocking sends refuse command lines the completion-signal splice would break (a trailing unquoted `&`, an unfinished `&&`/`||`/`|` continuation, an unquoted `#` comment, an unclosed quote, a trailing `\`), naming the problem and remedy, instead of stalling to the full timeout and falsely reporting the command "may still be running"; quoted and escaped operators stay inert and non-blocking sends remain byte-exact (pre-ship P1-6). The blocking signal's pane echo is scrubbed from model-facing output even when the 160-column wrap splits it, anchored to the session's own wait channels so lookalike agent text survives (P1-7). The cast clip marker now states what is always true: the tail is kept under the store cap, and the evidence record carries the full raw stream when evidence is enabled.

- `inspect sandbox cleanup range` (cli_cleanup) now tears down each project through its host lease's recorded origin, the reaper's discipline, instead of the ambient `INSPECT_RANGES_HOST`: a lease whose origin does not resolve in the cleanup shell is refused with both leases left findable (previously a vacuous local down deleted the host lease, stranding a separated backend's still-running range and the applier's host-side state) (pre-ship P1-3).

Teardown is deny-first through `down` (an unresolvable origin or failed provider reclaim refuses before any range resource is touched; the box dies before its NIC); the box's missing console lands as a declared in-chain evidence gap (`console-external-attack-box`) instead of a silently absent stream; doctor gains the Attack box group with a standing containment warn. Selection is deployment knowledge, never `range.yaml` (`boot.json` gains only descriptive facts: guest `kind`, attacker sizing and per-interface `network`/`ip`/`prefixlen`/`gateway`, so the same bundle digest realizes identically either way), builds pin the variable off, and a foothold range is excluded by construction. The governance story is the published conformance battery, `inspect-ranges attackbox verify --spec <range.yaml>`: capabilities declared honestly, realize through the real `up`, the attacker-surface sweep against the foreign box (the conformance stage's first live-range entry point), daemon-session stability, exec parity as inspect-ai's full sandbox `self_check` suite with an empty xfail pin (also run in CI against the in-tree fake provider over the production dial path), the exec witness as must-serve (settling execve-witness-v1's parked question: a marker exec must appear in the box's `exec/<guest>` stream with honest cursors, so `exec_events` and the event shape become external API; a typed refusal or an eternally empty ring fails), and teardown hygiene; a provider boots when it passes, and a range with an external attack box carries the weaker of the two containment stories with the battery as the stated floor (docs: Attack Box, Security). The Attack Box article also becomes the home of the default attack box's documentation (the catalog `attack` image's OS, build-asserted tool contract, and package manifest, previously on Images, plus boot defaults and custom images), with the provider seam as its second half.

- BREAKING (rebake): the exec witness (design: execve-witness-v1.md; concept adopted from glovebox PR #15, with attribution). The guest control daemon gains a kernel process-connector subscriber serving a new `exec_events` wire verb (protocol stays v3 on the `forward` wire-stable precedent; daemon bundle 3.3.0), and the provider polls every Linux guest during samples, shipping each `execve` (pid, ppid, uid, sanitized byte-capped argv, guest timestamp) to a hash-chained `exec/<guest>` evidence stream with decidable coverage on `exec-meta/<guest>`. The subscriber is LAZY-ARMED by the host's first poll, so builds never activate it and `INSPECT_RANGES_EXEC_WITNESS=0` is a complete kill switch with no image rebuild; a Windows guest or a connector-less kernel yields one declared `unsupported` record (the declared capability drop) instead of silence; loss is never silent (a bounded 4096-event overwrite-oldest ring whose overwrites surface as counted `exec-ring-overflow` gaps, kernel-side drops as `exec-subscriber-loss`). Record-only v1: no goal type and no corroboration reads the stream, so no existing range's score can move; wiring it into scoring is a future amendment of its own. The fork-storm battery (design/spikes/exec-witness) gates on numbers and ran 10/10 green: 5364 exec/s sustained for 60s with ping p95 14.3ms, zero listener restarts, 4.7 MiB RSS delta, and exact loss accounting. The bundle digest moves, so goldens re-derive and builds re-key (republish day).

- `inspect-ranges build` warns when a cached catalog image diverges from its fleet pin (the fleet-pass finding: a stale cached attack image booted silently against a moved pin and broke a chain mid-eval). `pull_image` now records the published root each catalog name landed from (`<name>.pull.json` beside the cache file, refreshed on every pull including converged ones; cache-local bookkeeping, never a traveling sidecar), and the build compares that record against `INSPECT_RANGES_PIN_FILE` for every image the spec names, attacker default included, emitting a `resolve` WARNING with the `images refresh <name>` hint on divergence. - `terminal()` is now the documented default tool for react-style range tasks, and every shipped example wires it (`react(tools=[terminal(), verify_goal()])` in all seven task definitions, READMEs, and the docs snippets). The decision rides the two-arm fleet pass data (design: fleet-pass-2026-10.md; the DECIDED entry in terminal-tool-v1.md): same caps both arms, terminal flipped equifax, goad, and splunk from failures to full scores via held reverse shells, parallel sessions, and a persistent query console, with no message economy on easy tasks (the measurement caveat stays in the docs: tool surface changes measured difficulty, so compare like with like). - Scoring reads current traffic: the scorer snapshots every segment's active capture chunk before any pcap read (`CaptureStreamer.flush`, exposed as `EvidenceSession.flush_capture` and `RangeOracle.flush_capture`). Size-based rotation meant a quiet segment's beacon sat in the still-active tcpdump file at scoring time, so live evals corroborated over zero bytes (the fleet-pass finding); the snapshot is a copy-ship (no claim, no removal: the file still ships complete at rotation or harvest), duplicate bytes across the snapshot and the final chunk are accepted, and the evidence record still seals and verifies. Local capture only; under the separated topology the applier owns the streamer and the flush is a recorded follow-up.

- Terminal tool viewer and output UX (from the fleet-pass viewer review): the call view is now compact (`terminal send · main` as the title, fenced keystrokes as the body; the screen-at-call-time snapshot and its store plumbing are gone, the asciicast is the session's visual record), a determinable delta returns raw with no `New Terminal Output:` header (the `Current Terminal Screen:` label survives only on the fallback, which tells the model a re-render is not new output), the blocking signal's pane echo (`; tmux wait -S ir-done-...`) is scrubbed from model-facing results while casts keep the raw pane, and reads skip the extra visible-screen capture when the delta is determinable.

- Non-stealth `detection` goals latch on first export match (the twelfth scoring-integrity amendment, from the first real-model fleet pass, where the signal was evidence-proven present and the trailing `window_s` still read it absent at scoring time): the telemetry poller gains caller-injected `SignalWatch`es (byte patterns over every shipped delta, command and file sources alike, with a carryover tail that drops at every recorded discontinuity so a match never bridges non-adjacent bytes; the poller stays records-only), `challenge_setup` arms one per non-stealth detection goal, and a match latches `achieved` at ship time through the first-pass-wins latch the scorer already consults, so the end-of-run window read confirms but never erases it. Stealth detection and `evade` keep end-of-run windowed semantics; the window read stays the fallback pass path.

- `range_apparatus`'s `reachability/declared-unreachable` detector no longer fires on `connection refused`: a refusal is an answered RST, so the address was reached and the port was closed, which is ordinary recon against any reachable host (two false positives in the first real-model fleet pass, one on a recon task whose correct answer is the refusal). Drops and timeouts (`no route to host`, `connection timed out`, `network is unreachable`) remain the violation signals, and the finding's hint now says so.

- The `terminal()` tool gives agents persistent tmux sessions on the foothold (design: terminal-tool-v1.md, session mechanics adapted from terminal-bench's Terminus, Apache-2.0): one action-dispatch tool (`open`/`send`/`read`/`close`) over named sessions, keystrokes verbatim with tmux key names, duration-based polling or shell-only blocking sends (the completion signal is refused when the pane's foreground command is not a shell, so it is never typed into a caught reverse shell or msfconsole), and delta results labeled honestly when the scrollback anchor is lost. The transcript renders each call against the screen the model saw when it issued it (the view binds before execution, so the store-snapshot it reads is exactly the decision-time screen), with no model_input filtering: results are plain delta strings. Each open session records through one streaming `exec_remote` tailing its pipe-pane sink: host-timestamped chunks mirror to a `terminal/<session>` evidence stream, and at close or sample finalize an asciicast v2 with per-call markers lands beside the evidence (`terminal-<session>.cast`). Capture needs a range sandbox and degrades to off elsewhere; the tool itself works anywhere `sandbox().exec` does and is opt-in task wiring, never a default (adding it changes measured difficulty). `tmux` joins the attack image's asserted tool contract (recipe v4; republish on the next catalog publish day).

- The build's behavioral trio exempts model-graded (`judge`) goals from its scoring (design: judge-at-build.md): the build has no model, so each check scores the challenge over its non-model-graded goals (the weighted mean renormalizes over that share, and the negative checks' one-submission floor reads it too), with the exemption recorded as `judge-exempt=<goal ids>` in the `behavioral` stage line and the manifest's check records. A challenge whose goals are all model-graded has no provable share and refuses `challenge-not-provable` before any chain runs. Eval-time scoring is unchanged: judge goals grade at eval under the engine's 25% weight-share cap, which also bounds what the exemption leaves unproven. First consumer: splunk-detection realizes its deferred `telemetry-report` judge goal on `execute-and-confirm-t1003-001` (weight 0.25, inside the cap); the example is local-only, so no published build invalidates, and its local build and battery want a re-run.

- `scheduled_activity` is realized (scheduled-activity-v1): the build installs each declaration as a persistent unit in the captured image (a systemd service plus timer on Linux, a scheduled task registered via `Register-ScheduledTask` on Windows, running as the declared `user` or root/SYSTEM), so every consumer boot runs the activity on its schedule with no per-sample work, and the runtime-only path keeps refusing unbuilt declarations. Scripts resolve from `activities/<script>` beside `range.yaml` and are content-digested into the manifest and the guest's build key, so an edited script rebuilds exactly the guests that declare it; the v0 `schedule` grammar is `@boot` or `every <N>s|m|h` (anything else refuses at validation with a positioned `invalid-scheduled-activity`; a missing schedule refuses at build resolution, as does a seconds interval on a Windows host, whose task scheduler repeats at one-minute granularity). Verification gains the `activity` kind: after realization the build checks that each unit or task exists and is enabled (`systemctl is-enabled` / `Get-ScheduledTask` state, `activity-not-verified` on failure), derived from the spec alone so the proof boot re-checks the captured artifact, and the manifest records per-guest activity records beside the recipes. A host declaring only `scheduled_activity` now counts as a content guest (built, captured, gated by `range-not-built`); no published build declares the section, so nothing published is invalidated. `examples/splunk-detection` consumes it: `benign-admin.ps1` on the endpoint every 10 minutes (service queries, directory listings, event-log reads) puts ordinary background telemetry on the instrumented endpoint; the fixture is local-only and its next build re-keys the `win` guest (docs: Guests, Building, Operations).

- Per-sample variable draws, v0 (executes the boot-draw recommendation parked in linux-examples-v1): a range variable may declare `draw: boot`, and each sample then boots with its own drawn value instead of the checked-in default. Builds are untouched: defaults substitute at load exactly as before, realized images, build keys, and the plan never see a draw. The provider draws per sample (deterministically from a fresh recorded seed) and renders the values into every Linux guest's cloud-init seed at `/etc/inspect-ranges/draws.json` (a JSON mapping of variable name to value), the agent's foothold excluded since a drawn value is often a challenge's expected answer; applying a draw is the range author's job, via a recipe-installed boot unit that reads the file and reconfigures the service. Drawable types are `port` (bounds default 1024-65535), `int` (explicit `min`/`max` required), and `choice`, each drawing uniformly while EXCLUDING the declared default, so a drawn variable never realizes or scores the one value every repository reader knows; `password` refuses `draw:` (per-sample secrets stay the plant layer's job) and `text` has no constraint vocabulary yet, both at validation (`invalid-variable`). Scoring follows the draw: `answer` goals with a `variable` source compare against the sample's drawn value when one exists and the declared default otherwise (`oracle.variable_value`, the one home of the rule; `oracle.draws()` exposes the mapping), and the seed and values are recorded verbatim on the new `draws` evidence stream (non-secret by construction), so recorded samples re-derive post-hoc; the build manifest's `seeds` slot stays a build-side record and stays empty. The build's behavioral proof boot draws like a sample, so boot-apply units and chain value discovery ship proven; its settle gate verifies declared services against a drawn view of the spec (`substitute_variables` gains an `overrides` argument), since the apply units have moved them off the substituted defaults. First consumer: kypo-demo's `telnet_port` declares `draw: boot` and the `kypo.server` recipe installs the `kypo-apply-draws` boot unit that moves telnetd to the drawn port, which the `find-telnet-port` answer goal then scores. BREAKING for the published kypo-demo build: the spec hash moves, so consumers refuse `no-build-for-spec` until the range is rebuilt and republished (docs: Guests' Variables section, Challenges; design: variable-draws-v0.md).

- Custom range host backends are registrable: `INSPECT_RANGES_HOST=<module>.<factory>[:<config>]` names a `HostBackendFactory`, imported and called at resolution, alongside the unchanged `local` and `uds:<socket>` built-ins (the value splits at the FIRST colon, so configs may contain colons). The variable's value IS the registration, by design: it is persisted verbatim as each lease's `origin`, so a fresh process (the reaper foremost) re-resolves teardown from disk alone wherever the backend's package is installed, with no registry call or companion variable to keep in sync. The factory returns a `HostBackend` bundle: the `HostProvider`, plus for a separated deployment the one `channel_for_lease` hook the runtime derives its boot/teardown/channel seams from (the uds backend's seam derivation, extracted to generic machinery and dogfooded: `local` and `uds:` resolve through the same bundle shape), an optional reaper reclaim connector, and an optional doctor probe. The protocols went public in the new `inspect_ranges.host` module, channel tier included (`Transport`, `MessageChannel`, the message models): a realistic backend implements one `Transport` and inherits the whole wire discipline. Error posture tightened on the way: an unresolvable value now refuses at `ProviderRuntime` CONSTRUCTION (previously only after admission, CID lease, and a full render), the reaper reports `origin-unresolvable` and reclaims NOTHING for an origin it cannot import (previously any non-`uds:` origin fell through to a local `down`, which for a remote host would "succeed" vacuously and release the lease over a still-running range; one-shot `reaper` exits 1), and `doctor` resolves the selected backend, runs its probe, and warns about lease origins its environment cannot resolve. The `RangeChannel` protocol also picks up the `gap_allowances` keyword `MessageChannel.realize` already had. Entry-point scheme aliases remain a compatible future addition (docs: Range Host, the new `inspect_ranges.host` reference).

- Mid-run `challenge_scorer()` invocation is now a supported contract, so react's `attempts > 1` works with challenge tasks (previously a warned misuse with `attempts=1` guidance). A mid-run invocation (react scores each submission with the task scorer; detected via `state.completed`) returns an intermediate verdict: the fraction of verifiable goals (the submission-taking types) already achieved among the latched records, reading exactly 1.0 once every verifiable goal is achieved, which is what ends react's attempt loop (react treats a submission as correct when the score value converts to 1.0). End-of-run goal types are excluded from the denominator (an agent that finished everything checkable must not read "incorrect" over goals it cannot influence mid-run) and their pending ids land in the metadata (`pending_goals`, alongside `intermediate` and the existing `mid_run_invocation` key); a challenge whose goals are ALL end-of-run types has zero verifiable goals and every intermediate verdict reads 0.0, so react burns its remaining attempts and ends. No end-of-run machinery runs mid-run (no probers, no corroboration, no `patch` exploit re-runs; the poller and verification context stay live), an intermediate verdict is never recorded as the final score (the end-of-run invocation remains the single authority, and repeats still return its recorded result), and the mid-run log line drops from warning to info. The `range_apparatus` scanner still reads the final verdict from the last non-mid-run score; its `scoring/mid-run-invocation` finding is removed, because a supported invocation is not an anomaly and zero findings stays the healthy state.

- Fix a transient boot flake: `StageLog.log` now recreates the project state directory before each append. Teardown is process-independent by design, so a sweep from another process (`down --all`, `cli_cleanup`, the reaper) could remove a booting project's state dir between stage writes and crash `up` (and so sample init) with `FileNotFoundError` on `stages.jsonl`; the write now lands in a recreated directory instead. Nothing reads directory absence as the torn-down signal (registration keys on `owner.json`, which the recreated dir does not have, and sweeps are idempotent), so a resurrected dir is harmlessly re-swept.

- Internal refactor, no behavior change: ACL rule-evaluation semantics (empty ACL is a plain accept-all router, any declared rule flips to default-drop first-match in declaration order, deny entries shadow by position and proto/port coverage, implied `established,related` return traffic, endpoints classified via `endpoint_kind`) now live in one shared evaluator, `_compiler/acl.py`. Both consumers plug in there: `render_router_nftables` emits one nftables rule per element of the evaluator's flattened first-match stream (`acl_entries`), and the scanner reachability model asks `acl_admits` directly, deleting its hand-mirrored copy of the contract, so a renderer semantic change can no longer drift from what `range_apparatus` expects. Invariance proof: rendered rulesets for the representative fixture set (plain router, allow rules, deny shadowing, CIDR/guest/network endpoints, routed-network endpoints) were captured on the pre-refactor path and pinned as byte-identical expected strings in `test_compiler.py`, and the 13 reachability contract tests pass unchanged.
