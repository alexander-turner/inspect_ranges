# External architecture review (2026-10-04): findings triage

*A second (fresh-context) coding agent reviewed [ranges-overview.qmd](../ranges-overview.qmd), the decision records, example ranges, spike documentation, and schema code, and checked platform assumptions against upstream documentation. It returned 11 prioritized findings. Every checkable claim was verified against this repo before triage (verification notes inline below); all were substantiated. No finding is dismissed; three are qualified. The reviewer's own headline matches ours: the core runtime architecture (KVM/libvirt, VM attacker, compiled networking, out-of-band control, immutable base images) stands; the gaps cluster around evaluation validity — proof of success, post-escape semantics, and fresh samples from saved state — which lead the next phase.*

## Also reconciled (reviewer's closing note)

- host-provider.md said both "only ever realizes ranges against the local Docker daemon" and "the host-interface path is fully supported" — reworded: ranges are realized against the Docker endpoint the deployment supplies (local daemon under sharding; HostProvider-supplied per-sample endpoint when separated).
- The architecture ledger's status for the remote path aligned with host-provider.md.
- Overview claims that shaved spike qualifications (capability floor, snapshot warm-cache, teardown) now carry them.

## Outcomes (executed 2026-10-04, same day as triage)

- **Docs**: all overview and record corrections above are applied; [scoring-integrity](scoring-integrity.md), [range-build](range-build.md), the network-authority and scaffold-compromise sections of [agent-containment](agent-containment.md), and the integrity section of [image-distribution](image-distribution.md) are written; examples are labeled as fixtures.
- **Code (finding 6)**: semantic validators implemented and tested (68 tests green; all six examples still validate) — duplicate IPs per segment, network/broadcast addresses, `dns.authoritative` existence + attachment, ACL endpoints vs router attachment, duplicate router attachments, `from == to` rejected.
- **Spikes run, all passing**: [hardened-container](../spikes/hardened-container/README.md) (finding 3: the measured eight-capability floor, non-root QEMU, default seccomp/AppArmor, zero cost; egress conformance holds through simulated router compromise); [checkpoint-clone](../spikes/checkpoint-clone/README.md) (finding 4: bundled checkpoints, 3 s independent per-sample instantiation, named CPU model, no cross-sample residue); [viosock](../spikes/viosock/README.md) (finding 8: the stable ISO ships a WHQL-signed Windows vsock driver; host↔guest stream data verified — the OS-split transport is packaging, not platform). Follow-through, same day: the Windows daemon port landed ([vsockd-win](../spikes/vsockd-win/README.md)) — `self_check` 40/44 with zero unexpected failures, 570/570 soak, 400/281 MB/s — unifying the control plane and retiring ISO hot-plug for Windows targets.
- **Remaining queued** (architecture.md §13): Inspect mid-run log sync, evidence streaming path, EBS/FSR measurement, the Windows daemon port, NAT-granted egress conformance; next-phase design directions recorded in architecture.md §14.

## What the review got right about our records vs our overview

A pattern worth keeping in mind for future documents: in nearly every finding, the decision records and spike READMEs already contained the honest version (prototype container posture, the `pkill` lifecycle note, the to-verify on GOAD egress, the untrusted-daemon-replies rule) and the overview compressed the qualification away. The overview is the document reviewers read first; it must carry the qualifications itself or point at them explicitly.
