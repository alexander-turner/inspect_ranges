# Provider v1: the Inspect SandboxEnvironment, with layered retry as a first-class requirement

*Phase plan for the provider track, successor to [realizer-v1](realizer-v1.md) and [channel-v1](channel-v1.md). It wires Inspect's `SandboxEnvironment` contract (verified against inspect-ai 0.3.272) onto the proven seams: `render_bundle` into `up`/`down` into `MessageChannel`. The driving operational requirement, from experience running other sandbox providers: infrastructure flakes, and losing an entire sample when a retry would have recovered it is worse than the double-execution risk of retrying, so sandbox operations retry by default with the idempotency assumption acknowledged. Prior art surveyed before design: the built-in Docker provider, inspect_k8s_sandbox, and the Modal/E2B/Daytona providers in inspect_sandboxes. New code lives in `src/inspect_ranges/_provider/` (files inside drop the underscore), registered through the existing entry point. Lockstep rule throughout: implementation plus failure modes plus battery plus docs plus fresh-context review, or the slice is not done.*

## Settled decisions

- **Boot per sample.** Each sample renders its own bundle and boots fresh; checkpoint restore arrives later with the build phase as a pure optimization.
- **Interrupted samples defer teardown to `task_cleanup`** (the Docker provider's convention). An interrupted range stays booted but hypervisor-isolated and egress-controlled until run end; the deferral is registered on Inspect's lifecycle scope so the sweep provably fires.
- **The root daemon is fixed in this phase**: channel operations default to an unprivileged `agent` user unless `user=` overrides, closing the three known self_check permission failures and answering "which user is the agent" correctly.
- **`timeout_retry` is advisory and ignored** (the k8s provider's documented stance). The in-guest deadline is authoritative: a command that hit it genuinely timed out, and re-running it in a range is destructive. The infra-flake class Docker's re-run ladder exists for is covered by the layered retry below.
- **Executed-but-lost results retry by default** (`ESTALE`, and unknown fates after a daemon restart surface distinctly rather than retrying). The k8s idempotency caveat is quoted verbatim in docs: retries cannot guarantee idempotency; a command that partially executed before the error may run again.
- Scope: co-resident topology only; no checkpoints; no evidence streaming; Windows and guest-content ranges stay gated at planning, so v1 runs networking-complete ranges.

## The retry architecture (the spine of the phase)

Four layers with distinct identity rules:

- **Layer 1 (built, channel):** wire-level same-id resend with endpoint dedupe, durable acked results, `ESTALE` tombstones. Exactly-once within one daemon lifetime; the poll-by-id completion oracle makes retry decisions lookups, not guesses. Prior art had to invent weaker versions of this (k8s stdout sentinels, Docker's stdin-written flag).
- **Layer 2 (new, `_provider/retry.py`):** bounded fresh-id retry around whole sandbox operations, built on tenacity (new dependency). The classifier's deny-list outranks its allow-list, and unknown errnos default to PERMANENT. PERMANENT: `TamperError`, command-layer `ChannelBudgetError` (a real timeout), `GuestError` with permanent errnos (EACCES, EPERM, ENOENT, EISDIR, ENOTDIR, EINVAL, E2BIG, ENOEXEC, EFBIG, EROFS), `FileLimitExceeded`, `UnicodeDecodeError`, output-limit errors, `SessionChangedError`. TRANSIENT: `TransportFailure` (including `ESTALE`, per the settled policy), channel/untimed `ChannelBudgetError`, transport-level `OSError`/`ConnectionError`. Consensus policy numbers from prior art: 3 attempts for exec, 5 for file ops, `wait_exponential_jitter(initial=1, max=10)`, `reraise=True`, and one shared deadline across all attempts so retries never exceed what the caller asked for. Env knobs read at provider construction: `INSPECT_RANGES_RETRY_{EXEC_ATTEMPTS,FILE_ATTEMPTS,WAIT_INITIAL_S,WAIT_MAX_S,UP_ATTEMPTS,DISABLE}`. Retries are telemetry: a structured log line per retry (guest, op, attempt, cause, sleep) joinable with the request-id logs, plus per-op counters surfaced in the debug bundle. Teardown and cleanup paths never retry.
- **Layer 2b (new, protocol plus provider):** daemon session-id invalidation. Wire exactly-once holds only within one daemon lifetime; a restart empties the dedupe store, so a resend can double-run and in-flight fates become unknown. `PongReply` gains a required `session` field (one field on one kind, minimizing three-codec churn). The provider pins each guest's session at `sample_init`; after a transient failure, or a success that needed a same-id resend on a side-effecting op, it compares sessions before mapping or retrying. A changed session raises `SessionChangedError`: operator-visible, PERMANENT, fails the sample hard (deliberately not "sandbox unavailable"), then re-pins so fresh operations proceed. This is post-hoc detection of the k8s `PodReplacedError` kind; true exactly-once across a restart is impossible, and session honesty is a pre-compromise property.
- **Layer 3 (new, acquisition):** render/up failures with transient stage classification get one respin with a fresh project name (the Daytona rule: never retry a create with unchanged identity), after a best-effort `down` of the failed attempt. A readiness timeout counts as the one re-boot. Teardown is a single attempt with `down --all` as the backstop.

## Per-sample identity and admission

- **Project names:** `ir-<range>-<sanitized sample id>-<6 hex random>`, passed explicitly as `UpOptions.project` (`up`'s default keys on the spec digest, so same-spec samples would collide). The random suffix makes epochs, retries, and respins collision-free by construction; the `ir-` prefix keeps `down --all` and `cli_cleanup` sweeps intact.
- **CID allocation:** the provider partition is 10000 and up (beside the compiler default 3+, channel harness 2048-2999, realizer batteries 3000+). A flock-guarded `cids.json` under the ownership state dir leases a contiguous block of `plan.totals.guests` CIDs keyed by project; leases release on `down` and `cli_cleanup` prunes leases whose project has neither an owner record nor live containers.
- **Working directory:** the agent user's home, `/home/agent`. Relative `cwd` and file paths resolve host-side with `PurePosixPath` before anything reaches the wire; the daemon additionally defaults the exec cwd to the exec user's home.
- **Admission:** `default_concurrency()` returns a conservative env-overridable constant (`INSPECT_RANGES_MAX_SANDBOXES`, else `max(1, min(cpus // 2, host_mem_gb // 8))`). The real gate is a per-process weighted semaphore charged from `plan.totals` at `sample_init` against measured host capacity, refusing with a named error when a single range alone exceeds the host. Cross-process leases and an independent reaper are a recorded follow-up, not quietly promised.

## The slices

**Slice 1: retry engine and error taxonomy (pure CI).** `_provider/retry.py` and `_provider/errors.py`, the single mapping table from channel failures to the Inspect contract: ENOENT to `FileNotFoundError` with the path in the message, EISDIR to `IsADirectoryError` with "directory" in the message, EACCES/EPERM and the rc-126 sniff to `PermissionError`, signed rc to the 128+N shell convention, command-layer budget to `TimeoutError` with `truncated_output` attached, post-retry channel/untimed budget and `TransportFailure` to `SandboxUnavailableError`, `TamperError` deliberately unmapped (a tampering guest must never read as "temporarily unavailable"), daemon stream truncation to a properly constructed `OutputLimitExceededError`. Acceptance: classification total and table-driven, shared-deadline arithmetic proven, `DISABLE` collapses to one attempt, the k8s caveat quoted verbatim. Battery: CI with LoopbackTransport fault injection. Review weights: deny-outranks-allow ordering, any PERMANENT swallowed into a retry, deadline math, telemetry byte caps.

**Slice 2: provider skeleton, lifecycle, ownership, layer 3 (CI via injected seams).** `_provider/provider.py` (`@sandboxenv(name="libvirt_range")` registered via `_registry.py`), `state.py`, `naming.py`, `admission.py`. `sample_init`: admission, CID lease, per-sample `render_bundle(PlanOptions(cid_base=...))` into staging, handle registered on `SandboxLifecycleState` before `await asyncio.to_thread(up, ...)` (`up` runs its own event loop), a long-lived `MessageChannel` from `UpResult.guests` with non-readiness budgets, session pins, sample files and setup script, environment dict with the attacker first (first key is the default sandbox). `sample_cleanup(interrupted=True)` marks the handle deferred; `task_cleanup` sweeps deferred and leaked handles aggregating failures and honors `cleanup=False` (leave up, print the recovery commands); `cli_cleanup` drives entirely from on-disk ownership in a fresh process; `OwnerRecord` gains optional provider-origin fields. Layer 3 wraps render/up with stage-classified respin. Acceptance: concurrent same-spec samples get distinct projects and disjoint leases (cross-process flock contention proven), handle registered before boot, interrupt-defer-then-sweep works, respins use fresh identity, every `sample_init` early exit unwinds lease/staging/registry. Review weights: ownership-before-resource ordering, unwind completeness, no retry on any cleanup path, lifecycle-scope registry rather than a ContextVar.

**Slice 3: the op surface, self_check on CI, the latency milestone.** `_provider/ops.py`: the 8-parameter `exec` (the proxy inspects arity), `timeout` to `Budget(command_ms)`, `timeout_retry` accepted and ignored with the stance documented, exec output decoded with `errors="replace"`, per-call `SandboxEnvironmentLimits` reads (they are ContextVars; self_check overrides them), `read_file` passing the limit as the channel cap with strict text decode, `write_file`, and `connection()` as an honest `NotImplementedError`. Host-side channel changes: the exec bulk cap becomes a parameter, and outcomes carry an `attempts` annotation for layer 2b. New conformance case: ~1 MiB argv through the chunked control frames. The self_check harness runs inspect-ai's full suite in pytest against a new `LocalEndpoint` (a FakeGuest variant executing real argv under a temp root, since the stock fake cannot run `sh -c`), with a short two-sided xfail list for CI-environment limits, then the latency-mock run that [range-channel](range-channel.md) requires, with wall-clock and exchange-count budgets. Review weights: the mapping table against the self_check source line by line, fresh-id retries only after the oracle's verdict, limits read per call and never cached.

**Slice 4: the daemon/protocol batch (one cross-codec round trip).** Everything needing a daemon rebuild, vector regeneration, or golden re-derivation, batched. (a) Session id: the required `session` field on `PongReply` in all three codecs, regenerated vectors plus a shared-rejection-table case, `SessionChangedError` and a `MessageChannel.session()` helper, `FakeGuest.restart()` so the double-run-detection path is CI-tested. (b) Agent user: the daemon defaults to `agent` when `user` is absent, exec via absolute-path `/usr/sbin/runuser` (closing the PATH-resolution privilege-escalation surface), file ops via setfsuid/setfsgid plus setgroups on a locked OS thread, unknown user as an errno error. (c) The golden recipe creates the agent user; RECIPE_VERSION 4; daemon-bundle re-pin. Acceptance: three-codec byte-exact vectors, session stability and change pinned in Go and C#, the loopback resend-across-restart test surfaces `SessionChangedError`, the derive battery proves default exec runs as `agent` and a root-owned write returns EACCES, and the compose-harness self_check reaches 44/44 with the xfail pin updated two-sidedly. Review weights: codec parity (the table, not the struct), privilege-drop correctness (setgroups, locked threads, error-path restoration), the session-spoofing honesty note, vector regeneration reviewed as a protocol change. Known hazard: stale-golden/new-host mixes fail tamper-shaped; a doctor version check and a migration note mitigate.

**Slice 5: booted-range integration and the real eval (VM batteries, both devboxes, discharging the realizer phase-exit carry-over).** A `design/spikes/provider-v1/` harness: provider-driven lifecycle on a real multi-guest spec, self_check 44/44 pinned, the portable conformance suite over the provider's channel, and the retry battery against real faults (the daemon unit restarted mid-sample surfaces `SessionChangedError` with a loud sample failure and clean teardown; a paused guest's transient failures recover within deadline with the counters moving). The lifecycle matrix on real VMs: Ctrl-C mid-sample defers then sweeps, `kill -9` of the eval process recovered by `inspect sandbox cleanup libvirt_range` from a fresh shell, `cleanup=False` leaves the range up and the printed command removes it, and two same-spec samples run concurrently with distinct projects and disjoint CIDs. Zero `ir-` residue after every scenario. Finally one real `inspect eval`: sample files plus a setup script, a solver that execs on the default sandbox and `sandbox("web")`, a scorer reading a guest file, green end to end through pure entry-point registration. Review weights: battery vacuity, the honesty of the 44/44 pin, concurrency evidence quality.

## Logging and debuggability

Retry telemetry joins the existing request-id correlation story: every retry logs one structured line (guest, op, attempt, cause, sleep) and increments per-op counters; the debug bundle gains the counters; `SessionChangedError` messages carry both session ids and the op that triggered the comparison. Acquisition respins log the failed project name and its diagnosis before the fresh attempt.

## Non-goals and recorded follow-ups

Cross-process lease/reaper admission; a `connection()` console command; `forward`; evidence streaming; Windows through the provider (gated until the build phase); HostProvider/separated topology; checkpoint boot. Open risks stated for the review rounds: LocalEndpoint CI fidelity (the real gates are slices 4 and 5), the ESTALE double-run as a loud documented behavioral choice, session-field lockstep operator confusion, Go privilege-drop subtleties, and the `asyncio.to_thread(up)` executor ceiling (bounded by admission).

## Deviations and corrections (chunk 1, recorded 2026-10-09)

- **Large argv rides the wrapper script, not chunked control frames.** This record's slice-3 text assumed ~1 MiB argv could ride the chunked control frames; the protocol deliberately caps control payloads at ONE 32 KiB frame (only bulk chunks), exactly as channel-v1's clarification already documented. The provider implements the uploaded wrapper-script pattern (argv above 24 KB becomes `sh <uploaded script>`, written through the retried file path), and the full-size case is covered by self_check's own `test_exec_large_command`.
- **Sample files and the setup script are Inspect's work, not `sample_init`'s.** The contract runs `copy_sandbox_environment_files` and the setup script itself, through the environments `sample_init` returns; the provider only returns them. The slice-2 text implying the provider copies files was wrong against the installed contract.
- **Per-op shared deadlines default to attempts-bounded.** The retry engine supports a hard shared deadline (`RetryPolicy.deadline_s`, wall-time-true, with an in-flight attempt truncated and surfaced as `TransportFailure`), but the op surface does not derive one from the caller's exec `timeout`: a transient failure consumes none of the command's budget semantics, and retrying with the full timeout each attempt is the k8s-consistent reading. Callers needing a hard wall set it through the policy.
- **The loopback endpoint's inbound cap was 32 MiB while the daemon accepts 256 MiB**; the 50 MiB self_check cases caught the fidelity gap and the reference endpoint now mirrors `DAEMON_INBOUND_BULK_CAP`.
- **`CommandTimeout.truncated_output` is always `None` in v1**: the daemon's ETIME reply carries no bulk, so there is no partial output to attach (the record's text and the Docker prior art implied one). Slice 4 MAY add partial-output carriage to the ETIME `ErrorReply` as an optional protocol extension if the daemon batch finds it cheap; recorded, not promised. **CLOSED in slice 4**: the option was taken (see the slice-4 decisions below).
- **Process honesty note**: the slice-1 review fixes were committed folded into the slice-2 feature commit (9c586dc) rather than as their own fix commit; recorded here rather than rewritten. Slices 2 and 3 kept the separate-fix-commit discipline, as does everything after.

## Slice-4 decisions (recorded 2026-10-09)

- **ETIME partial output: TAKEN, as a capped TEXT field.** `ErrorReply.partial` (max 4096 UTF-8 BYTES in every codec, legal only with ETIME/ETIMEDOUT; the shared rejection table enforces both rules in all three codecs) carries the killed command's output tail: stdout when it produced any, else stderr, UTF-8-sanitized. Deliberately never bulk: the bulk-on-error side channel stays closed. The provider surfaces it as `CommandTimeout.truncated_output`.
- **Daemon-side write mode.** `WriteFileRequest.mode` (optional int, 0..0o7777) sets the created file's permission bits atomically with the write (create with the mode, then chmod past umask), replacing the provider's best-effort post-upload `chmod 600` round trip for the env-bearing wrapper script. The Windows daemon accepts the field for codec parity and deliberately ignores it (POSIX bits have no NTFS/ACL equivalent; stated in `Daemon.cs`).
- **Agent-user fallback is a warning, not a failure.** When the daemon is not root or the `agent` user does not exist (a pre-v4 golden), exec and file ops keep the daemon's own identity with a diag warning (`agent-user-unavailable`), so old goldens stay operable during migration UNDER A NEW DAEMON. The inverse mix (an old 3.0.0 daemon pinged by a slice-4 host) fails the host's strict decode because `session` is required, and surfaces tamper-shaped: exactly the known stale-golden/new-host hazard this slice recorded, mitigated by the slice-6 doctor version check and a migration note (re-derive). The derive battery proves the real semantics against a recipe-v4 golden; CI hosts exercise the fallback path.
- **Privilege-drop mechanics.** Exec drops via absolute-path `/usr/sbin/runuser` (never PATH-resolved). File ops drop the FILESYSTEM identity per operation: setfsuid + setfsgid + setgroups on a locked OS thread; if any restoration step fails the thread stays locked so Go destroys it on goroutine exit, and a half-privileged thread never rejoins the pool.
- **Session honesty (restated for the wire)**: `PongReply.session` (32 hex, required) is minted once per daemon process; the provider pins it per guest at boot and re-checks after post-retry transients and resent side-effecting successes. Post-compromise a hostile daemon can report any session it likes: session change detection is a pre-compromise property, like layer attribution. Fixed alongside: the exec path's lost-reply resend (`ConnectionError` after send) now counts as a delivery, so the session-invalidation policy actually sees the risky resend (the CI restart test caught the gap).
- **Windows daemon**: gains session minting/emission and the ETIME partial; keeps its existing user model (the agent-user work is Linux-golden scoped; Windows guests stay gated until the build phase).
- **runuser quirks, measured and translated (review round).** util-linux runuser (noble) exits 1 for exec failures of the target command instead of the shell's 126/127; the daemon translates its unambiguous one-line diagnostics ("failed to execute X: No such file or directory" to 127, ": Permission denied" to 126) so the user-switched path matches the direct path, with the spoofing blast radius stated in code. And runuser ALWAYS resets HOME, SHELL, USER, LOGNAME, PATH (its whitelist option ignores exactly those five, verified empirically), so the provider routes env touching them through the wrapper script, whose exports run after the switch; a wrapper for an explicit third user (not agent, not root) widens to 0644 because that user cannot read an agent-owned 0600 file (the stated env exposure, now scoped to that one rare combination).
- **Mode-carrying writes pin bits before content (review round).** O_TRUNC ignores the mode argument on pre-existing files, so the daemon (and LocalEndpoint, in mirror) opens without truncating, fchmods to the exact bits, then truncates and writes: a rewrite of a formerly-0644 file never exposes the fresh secret through the old bits. setfsuid/setfsgid report no errors by design, so the privilege-drop legs verify by READ-BACK (a second call) and a non-verifying thread is retired, never returned to the pool.
