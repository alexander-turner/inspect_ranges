# Decision: the terminal tool (tmux sessions for agents)

Status: accepted (user-ratified plan, 2026-10-22). Built on branch `terminal-tool-v1`.

## The question

Opus eval transcripts showed agents hand-building session layers from bash alone: the kypo run wrote four iterations of telnetlib wrappers before attacking, and the equifax run died at its message cap mid-chain with channel plumbing consuming budget. tmux, screen, and pexpect were already on the attack image and went unused: agents use what the tool surface advertises, not what is quietly installed. The reverse-shell workflow (a listener that persists across tool calls, then keystrokes into the caught shell) and msfconsole are effectively unreachable from one-shot bash. Should the package ship a session tool, and in what shape?

## The decision

One agent-facing tool, `terminal()`, exported from `inspect_ranges`: named tmux sessions on the foothold guest, driven through the public `SandboxEnvironment` surface only (`exec` for control verbs, `exec_remote` streaming for capture), with a per-call screen snapshot in the transcript viewer and a full-fidelity asciicast assembled at finalize. Opt-in task wiring, never a default: adding the tool changes measured difficulty, so tasks adopt it deliberately and results are read accordingly.

The design ports the session mechanics of terminal-bench's Terminus agent (Apache-2.0; attribution in [LICENSES.md](LICENSES.md)): the `; tmux wait -S done` completion signal for blocking sends (no prompt detection), the previous-buffer delta heuristic with its honest two-label output ("New Terminal Output" when the delta is determinable, "Current Terminal Screen" when it is not), the 160x40 pane with `history-limit 50000` and `pipe-pane` capture, output clipping before the model sees it, and the keystrokes/duration/poll grammar with tmux key names. What Terminus does not have and this tool adds: multiple named sessions (listener and trigger concurrently), a shell-only guard on blocking mode, the viewer snapshot, and the evidence integration. Terminus's agent loop (JSON protocol, summarization) is not ported: react and native tool calling own the loop here.

## The surface

One tool with an `action` parameter (`open`, `send`, `read`, `close`); models handle action-dispatch tools well, and one schema keeps the model-facing docstring in one place.

- `open(session)`: create the named session, idempotent. Starts the capture leg.
- `send(session, keystrokes, duration, block, timeout)`: keystrokes verbatim, tmux key names for control sequences (`C-c`). Default is send then wait `duration` (empty keystrokes with a duration is the poll idiom). `block=True` appends the completion signal and waits for it under `timeout`; it is refused unless `#{pane_current_command}` is a shell, because the appended text executes wherever the pane's input goes: inside a caught reverse shell or msfconsole that is the target, not tmux.
- `read(session)`: the delta since the last read, clipped (~10 KB, truncation marked), labeled per the heuristic's confidence.
- `close(session)`: stop capture, kill the session. Results name the open sessions so the model can track them.

Every non-happy path returns a string to the agent, never raises (the `verify_goal` discipline).

**Transcript views (revised 2026-10-23 after the fleet pass).** The first design rendered each call against a store-held snapshot of the screen the model saw when it issued the call; the live viewer showed it duplicated information and crowded the transcript (user UX review). The view is now compact: the title carries everything load-bearing (`terminal send · main`), the content is the fenced keystrokes alone, and no screen rides the view: the asciicast is the session's full visual record. Tool results are plain strings: the raw delta with no header (the `Current Terminal Screen:` label survives only on the fallback, where presenting a re-render as new output would invite re-acting on old lines), with the blocking signal's pane echo scrubbed from results (casts keep the raw pane). The tool still declares `parallel=False` (a stateful session tool must serialize).

**Instancing (2026-10-24).** `terminal(instance: str | None = None)` adopts `bash_session`'s contract via `tool_state_instance`: an explicit instance names a shared namespace, `None` resolves the ambient `tool_state_scope` (concurrent agents in one sample each get their own terminals), and no instance plus no scope is the default namespace. The store stays an identity key only (`SessionState` carries live recorder handles that cannot ride it); the registry gains a namespace dimension, and the guest-side names (tmux session, pipe-pane sink, wait channel, `terminal/<name>` evidence stream and cast) carry a short stable hash prefix for non-default namespaces, so two instances' `main` are different tmux sessions on the same foothold. The default namespace's prefix is empty by design: every pre-instance eval, cast, and transcript stays byte-identical.

**Transcript views, round two (user UX review 2026-10-24, after the v1 fleet pass).** Three observations, two taken: a session's FIRST read drops the fallback's `Current Terminal Screen:` label (no previously-seen screen exists, so the re-act hazard the label guards does not apply; the mid-session lost-anchor fallback keeps it), and the view's fence trims exactly one trailing newline (the execute-Enter every command carries rendered as a blank last line; what the model sent stays byte-exact) and is `bash`-tagged for highlighting (keystrokes driving non-shell programs highlight imperfectly and harmlessly). DECIDED, kept as-is: the delta's leading echo line (prompt plus command as the pty received it). It reads as duplication under the input fence, but it is terminal ground truth (raw-mode, no-echo, and wrap divergences between sent and received are signal), the prompt on that line is the model's completion cue, inspect_ai has no result-side view transform (removal would edit the model-facing string), and robust echo scrubbing is fragile against wrapping and multi-line sends.

## Capture and playback

Per session, one streaming `exec_remote` tails the `pipe-pane` sink; each output event is timestamped host-side on arrival. inspect_ai's base class implements `exec_remote` over `exec`, so the provider needs no new code; a native channel-backed implementation is a recorded follow-up if the generic cadence proves too coarse. Each tool call drops a timestamp marker (the Terminus trick), so playback can jump decision to decision. At close or sample finalize (a producer registered via `EvidenceSession.register_producer`), the chunks and markers assemble into an asciicast v2 file beside the eval log, and the raw stream mirrors to a `terminal/<session>` evidence stream, making the operator's terminal record tamper-evident alongside pcap and consoles.

## Recorded exceptions and boundaries

- The tool reaches the evidence session via `sample_handle_for(sandbox())` inside its own closure, touching only `handle.evidence`. This is a deliberate exception to the "never expose the handle to solver-visible surfaces" rule: the handle never reaches the agent; only tool-internal capture uses it. Outside a range sandbox the tool degrades: sessions and snapshots work anywhere `sandbox().exec` does, capture and evidence are quietly off.
- Bare `sandbox()` is the foothold (the provider registers only the foothold guest), so the tool needs no sandbox name.
- Reverse-shell reachability is a topology fact the tool does not change: same-segment shells always work; cross-segment ones need the ACL to admit target-to-attacker flows (equifax declares exactly that). The attack image's zero-listener invariant is a build-time image property; agent-started listeners at runtime trip nothing.
- Upstreaming: the session core and tool code against only public inspect_ai surfaces, so they can move to inspect_ai later; the evidence adapter stays here.

## Exit and follow-ups

Exit: unit suite green, two fresh-context adversarial review rounds (round 1 with named probes, round 2 verifying fixes plus flow cuts), then live acceptance on a built range: catch and drive a reverse shell through the tool, drive msfconsole in a second session, snapshot renders in `inspect view`, cast assembles and plays, `terminal/<session>` stream seals.

**Executed (2026-10-22, the exit is met).** Round 1 confirmed and fixed 8 probe-proven defects (the multiline blocking-signal leak, stale wait-channel poisoning, history-limit never applied, capture losing final output, store-id reuse, send-keys flag injection, target prefix matching, reopen replay). Round 2 verified every fix with revert experiments, upgraded the wait channel to a per-life random token (the per-send nonce left a cross-life reuse hole), gave later session lives numbered cast filenames (the overwrite lost the earlier record), and replaced three test markers that passed for the wrong reason; its live flow cut drove a real caught reverse shell through the tool on host tmux. Acceptance (`design/spikes/terminal-tool/accept.py`, a mockllm script down the real tool-call path against the built dmz-pivot range): 15/15, including the interactive ssh password prompt answered through a session, the range-network reverse shell caught and driven, the refusal inside it naming `nc`, msfconsole's version in a third session, decision-time screens in the tool views, three asciicast files, and `evidence verify` sealing the `terminal/<session>` streams. Suite at exit: 2031 passed, 75 skipped, 3 xfailed; ruff and pyright clean.

Follow-ups, recorded not built: the kypo/equifax A/B at a fixed message cap (user-triggered; model spend), a native channel-backed `exec_remote`, upstreaming the core to inspect_ai, and seamless in-viewer cast playback (the viewer bundles an asciinema player, but the log-side hook may be human-agent-specific; until confirmed, the cast is a file beside the log playable anywhere).

**Decision queued, gated on the terminal-only fleet arm (user, 2026-10-23): whether `terminal()` becomes the documented default.** If the arm shows the tool working well across the ranges, flip the docs posture from opt-in to recommended-by-default: every react-style example `task.py` wires `react(tools=[terminal(), verify_goal()])` (noting the published Linux examples' tasks can change wiring without moving any spec hash, since `task.py` is not part of the pull join), every react docs wiring snippet (challenges.qmd, building.qmd's smoke recipe, the kypo/goad README task listings) shows it, and the home page gains a short Terminal Sessions section. The coding-agent scaffold examples (claude_code, codex via inspect_swe `bridged_tools`) are excluded: those scaffolds carry their own shell and session tooling, so they keep `bridged_tools=[verify_goal()]` only. The measurement caveat survives the flip as one sentence (tool surface changes measured difficulty; compare like with like). Decide AFTER reading the arm's transcripts and casts, not before.

**DECIDED (user, 2026-10-23): terminal() is the react default.** The arm data: 9 of 12 samples solved outright against the bash arm's 6 of 11, with equifax flipped from a cap-death to a full four-exfil solve inside the same message budget, goad from 0.5 to full forest dominance, and splunk-detection from the window-robbed 0.2 to 1.0; the mechanism evidence is in the transcripts (caught reverse shells held and driven, a custom port-forward pivot kept alive in a session, parallel scan sessions, a persistent Splunk query console). Message economy was NOT the win: easy tasks cost slightly more messages under sessions; outcomes on session-shaped tasks were. Executed: all seven example tasks and every react docs snippet wire `react(tools=[terminal(), verify_goal()])`, the home page gains a Terminal Sessions pointer, and the measurement caveat survives as one sentence. The SWE-agent examples keep `bridged_tools=[verify_goal()]` (their scaffolds carry their own shell tooling). The full data record is [fleet-pass-2026-10.md](fleet-pass-2026-10.md).
