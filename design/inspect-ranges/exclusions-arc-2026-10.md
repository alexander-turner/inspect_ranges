# Record: the exclusions arc (2026-10-28)

The targeted follow-up to [example-coverage-2026-10.md](example-coverage-2026-10.md): of that arc's recorded exclusions, three were worth running down and the rest were deliberately left (user-ratified scoping, same day). The selection rule: close what is cheap and load-bearing, skip what tests vocabulary or needs feature work no user has asked for.

## Taken

1. **The `dns.nameservers` build brick, run to ground.** The recorded "validation-warn candidate" turned out to be an ordering defect, not a missing-resolver defect: `egress_build_spec` APPENDED the build nameserver, `resolvers_for` orders declared nameservers ahead of later entries, and glibc tries resolv.conf in order (5 s per server, three entries honoured), so a declared-but-build-dead resolver burned the settle probe's 5 s budget before the working resolver was consulted, surfacing as channel noise. Fixes: prepend (the correction the Windows probe shape had already recorded), the settle message names the guest's resolver list, `build-nameserver-unanswerable` refuses a dead `--build-nameserver` up front, and the `dns-nameserver-unanswerable` validation warning (warning, never an error: a dead entry is legitimate eval-time scenario dressing, the defender-ops authoring intent). The unanswerable predicate is an explicit block list (documentation, benchmark, reserved, multicast, loopback, zero): `is_private` would be wrong (VPC resolvers are private) and link-local is excluded (AWS serves 169.254.169.253). Residual stated in the code: `dns.authoritative` entries and the records service still precede the nameserver list, so a network declaring three or more keeps the settle gate as that corner's tripwire. Re-exampling `dns.nameservers` is now unblocked but not taken.

2. **`lower_is_more_severe` consumed: defender-ops `quiet-journal`.** The watchdog mirrors health lines to stdout with syslog `<N>` prefixes (systemd's `SyslogLevelPrefix` turns them into genuine journald `PRIORITY` 6/5/3), a recipe-installed exporter ships `journalctl -u opswatchdog -o json` under the cursor-banner contract, and the cleanup challenge's fourth goal scores floor-4 numeric severity on a second sensor plane (the root-owned OS journal beside the agent-writable file log). The fresh-context review earned its keep here, finding the two defects of exactly the splunk-bridge class it was aimed at: (P0) the wrapper's banner padding made every empty poll ship one byte, so a stalled journal read as flowing and the goal's own "a stalled journal fails rather than hides" claim was false — closed in the wrapper (bare banner) and the engine (a whitespace-only quiet poll records bytes 0); (P1) a vacuumed-away cursor makes journalctl exit 0 and silently reposition, destroying unshipped alerts gaplessly — closed by the exporter's anchor check (the caller's cursor must round-trip to its exact record or the poll fails and `on_sensor_tamper: fail` prices it). Plus journald rate limiting off for the unit (floods price as truncation gaps, not silent drops). Stated floor, the lotl pattern: the stall route is proven by the exporter contract, engine tests, and recipe self-assertions, not by the trio — the behavioral checks run from the attacker foothold, and this range's ACL denies every path to the monitor except the crash port, so a journal stall is not an agent-available cheat here; the forged check's crash loop remains the maximal attacker-executable injury on that plane.

3. **The multi-agent terminal proof: `evals/multi_agent/`.** The first end-to-end consumer of the `ir_*` cast attribution headers (shipped 2026-10-25 with no consumer). A supervisor react agent with no terminal of its own hands off to `recon` and `exploit` sub-agents, each holding `terminal(instance=...)`, over kypo-demo; `check_log.py` asserts the cleave against the transcript's span tree. The real-model run scored the full ladder 1.0 with three casts across two agent spans, denormalized names faithful, tool spans parented correctly, and every cast flushed at finalize still carrying its opener's identity (the identity-at-open-or-never claim in its strongest form). Load-bearing authoring fact, now recorded for solver authors: nothing in inspect-ai sets `tool_state_scope`, so sub-agents sharing the default terminal namespace collapse into one session; distinct `instance=` per sub-agent makes the cleave structural. One prompt iteration was needed (the supervisor initially delegated everything to recon); the fix was scope-fencing, not mechanism.
