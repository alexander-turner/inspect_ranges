## Findings, ranked

### F1. Correctness, probe-demonstrated (A9 sibling arm): `RangeMeta.name` escaped the name-grammar discipline and traverses filesystem paths through the CLI `up` path

Round 1's A9 (fix `91f7150`) validated hosts, networks, routers, and the attacker, but not the range's own name. `RangeMeta.name` is a plain `str` (src/inspect_ranges/types.py:89) and `_name_issues` (types.py:1008 area) never checks it. On the CLI path the raw name becomes the compose project, `project = f"{PROJECT_PREFIX}{range_name}-{spec_sha[:12]}"` (src/inspect_ranges/_runtime/up.py:412), and the project becomes a path segment: `project_dir(state_dir, project)` is `state_dir / project` (src/inspect_ranges/_runtime/ownership.py:44-46), written by `write_owner` with `mkdir(parents=True)` (ownership.py:49-53) and later removed by `remove_project` via `shutil.rmtree(..., ignore_errors=True)` (ownership.py:76-78). The stage log and pulled console logs live in the same directory.

Probe (run in the worktree, residue cleaned): a spec with `meta.name = "../../../../../../ESCAPED-BY-RANGE-NAME"` passes `semantic_issues` with zero issues, renders a bundle green, and `up()` with a fake docker runner wrote `owner.json` to `/tmp/ESCAPED-BY-RANGE-NAME-a8c1eb6a294e/owner.json`, six levels above the state dir, before the first docker failure. Teardown would `rmtree` the same traversed path. The provider arm is safe because `sample_project` sanitizes (`_provider/naming.py:28-40`), which is itself evidence this arm was the missed sibling: the sanitizer exists precisely because raw names are not path-safe. Reachable from the documented user surface (`inspect-ranges up --from-spec`, `render` + `up`). Round 1 placed this exact consequence class ("`../../escape` writes outside the bundle") in Group A; the natural fix is one more entry in `_name_issues` (the validator A9 built is three lines away from covering it).

### F2. Correctness, concretely traced (A10 sibling gap, and an A10/B21 composition): the realize per-report allowance is sized for exactly one gap; B21's internal bounds exceed it everywhere else, worst on the pre-first-report image build

A10 (fix `25109b5`, floor from `20744b0`) widened only the verify-to-terminal gap: in `MessageChannel.realize`, `allowance = channel_budget_s` (180 s default) unless the last seen report's stage is `verify` (src/inspect_ranges/_channel/channel.py:951-958). Before the first report, `seen` is empty, so the allowance is 180 s. But `up()` runs `ensure_range_image` BEFORE its stage log exists (src/inspect_ranges/_runtime/up.py:437-446; the first `log.log` is line 448), and the applier emits reports only through `on_stage` (src/inspect_ranges/_host/applier.py:586-595), so in the separated topology the whole first-use docker build of the hypervisor image (apt-installing libvirt, qemu-system-x86, and friends, per the Dockerfile) sits inside the driver's 180 s first-report window. B21 (fix `2b861cc`), landed the same round, sized that very call at `IMAGE_BUILD_TIMEOUT_S = 1800.0` (up.py:42-43), ten times the allowance, and the doctor's realizer check explicitly blesses build-on-first-use as a warn ("not built yet; `inspect-ranges up` builds it on first use", src/inspect_ranges/_doctor/checks.py:687). The image rebuilds on every package upgrade or Dockerfile change (`RANGE_IMAGE_TAG` keys on `__version__`, the content label on the Dockerfile), so this is once per applier host per version, not once ever.

Consequence, same shape as A10's own trace: the driver fails with `ChannelBudgetError` (not a respin class), the sample fails infra-shaped, and the applier finishes the boot in the background, holding its admission charge and lease until reaper expiry. Lesser arms of the same unowned sum: the construct-to-boot gap carries `compose up --wait` bounded at readiness_timeout+60 (360 s default, up.py:489-500) and the boot-to-verify gap carries the guest-boot exec bounded at readiness_timeout (300 s, up.py:510-513), both above 180 s; these are rarely slow but B21 deliberately set them above the per-report envelope and nothing owns the composition. Note the fix round pinned the non-verify starvation as intended stall detection (`test_realize_verify_allowance_applies_only_to_the_verify_gap`), which is right for true stalls and wrong for the one documented-legitimate 30-minute operation. Local (non-uds) topology is unaffected. Relates to 25109b5 (A10), 2b861cc (B21), 20744b0.

### F3. Mechanical: the A6 phase budgets exist as four unanchored copies of the 6 s / 10 s pair

`_provider/evidence.py` defines `PRODUCER_STOPS_SHARE_S = 6.0` and `SEAL_RESERVE_S = 10.0` but passes literals `stop_timeout_s=6.0, harvest_timeout_s=10.0` to `streamer.stop` (evidence.py:536); `_host/applier.py` repeats both literals in its own stop call plus a separate `_EVIDENCE_SEAL_RESERVE_S = 10.0` (applier.py:279-296). The `FINALIZE_BUDGET_S` docstring's budget-composition argument depends on these numbers agreeing; drift at any one call site invalidates it silently, and the sealing lifecycle was this round's hardest-won fix family. Relates to c35f2ef, 8c4ae53, 1be2042, 20744b0.

### F4. Mechanical: the C# accept loop sleeps while holding `Native.InheritLock`, contradicting its own comment

The A1 review hardening wrapped accept-to-uninherit in `lock (Native.InheritLock)` with the comment "the lock is held only across fast calls" (Daemon.cs:308-313), but both accept-failure catch arms execute `Thread.Sleep(2)` / `Thread.Sleep(10)` before their `continue` releases the lock (Daemon.cs, the wedge-signature and accept-failed arms). Error-path only, bounded, no deadlock possible (the Exec side takes the same lock without blocking calls), but a listener error-storm serializes concurrent exec launches in 10 ms steps and the comment is wrong on this arm. Relates to 7ae012d / 6479463 (A1 review round).

## Considered and declined

- A6 seal reserve shared by the recorder drain and both seals (a slow host seal could starve the driver seal inside the 10 s): the declared guarantee is only that stops never starve the seal attempt; sub-splitting the reserve is hypothetical hardening and the hanging-sink case is tested and honestly logged.
- `_exchange` raises on reply timeout without a same-id resend (only connection loss retries): pre-existing deliberate semantics, documented in the docstring.
- realize passes the resume-attempt counter as `attempts` to `_expect` where exec passes delivery counts: each resume resends the same id, no consumer distinguishes the two meanings.
- `ExecOutcome(attempts=max(deliveries, 1))` belt-and-braces: traced that deliveries >= 1 on every success path; the max is harmless defense, not dead code.
- C# `CreatePipe` partial-failure handle leak on the EIO early return: pre-existing shape unchanged by the lock, one-shot error path.
- Go `openServedFile` opens char devices O_NONBLOCK then restores: side-effect-free for the pinned /dev contract; exotic device-open semantics are hypothetical.
- `processExited` pid-reuse window and the zeroed-Siginfo convention: documented in-code; the pid-reuse family is a recorded round-1 residual.
- ComposeTap lists by glob while LocalTap lists by regex: the glob is a superset and the streamer's regex classification treats both identically; verified `g*.pcap*` matches `.shipped`.
- B13 `claimed_pending` recomputed from each cycle's listing (a listing failure skips the segment for one cycle): retried next cycle, bound still holds.
- Telemetry truncated/cursor-missing arms mark `replay` without clearing `replay_next`: the reset that follows re-arms it anyway; double-marking errs in the honest, duplicate-decidable direction.
- `valid_sink_location` consumed only by the doctor (lockstep by adjacency to `sink_for_location`, not by shared call in the runtime): behaviorally lockstep today, in one file; a call-sharing refactor would be style.
- Attacker name validated only when no foothold host is named: with a foothold, the attacker name feeds no derivation; the foothold host's own name is validated.
- Duplicate-service-name reported at the duplicate index only: matches the codebase's duplicate-goal-id convention.
- images-list three-way recipe split duplicating the doctor's classification: three lines each, both independently pinned, drift would fail a test.
- Go A1 pin exercises AF_INET rather than AF_VSOCK: the flag is set by the shared helpers, family-independent, and the live battery covered vsock.
- B6 boundary (exit between timer and peek still reads timed out): documented as the pre-existing budget-edge semantics.
- `_disclose` records the plant before the write lands (a hard kill between record and write leaves a store record for a file that never existed): every raise path discards; the residue of a process kill is a store record the teardown clears.
- Recorded residuals not re-reported: T7, C# behavioral validation, second-cancellation owner-record residue, pid-reuse window, B10 platform divergence, `_in_window_chunks` span shape, duck-typed `FakePlantSession`, the egress spike's local bridge-name copy, the doctor's duplicated fix string.
